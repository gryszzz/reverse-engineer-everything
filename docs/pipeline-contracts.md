# Pipeline contracts

`/home/box/shared/ree-pipeline/contracts.md` was not on this machine and was not in the repository. This file is the contract the `pipeline` command implements. It does not describe a live Guard, Blast, Scale, or Vault API. Those names are files a person can send later.

## Command

```sh
node ree.mjs pipeline TARGET --out DIR [--name NAME] [--resume] [--authorized] [--json]
  [--improvements FILE] [--no-improve]
  [--approve-launch] [--approve-guard] [--approve-blast] [--approve-scale] [--approve-vault]
```

The studio button `Run owned web pipeline` posts `{ "fixture": "web", "product_name": "Board Desk" }`. The server resolves `experiments/ree-bench/web` itself. The button does not accept an arbitrary path.

## Stages

The stages run in this order. Each one writes `checkpoints/<stage>.json`. A failed stage writes `status: "failed"`, sets `stopped_at`, and does not run later stages. The process exits 1 and the stderr line is `pipeline stopped at <stage>. <why>`. Usage errors (missing `--out`, a target that is not a directory or an http(s) URL, a URL with embedded credentials, an output directory that already has `run.json` without `--resume`) exit 2.

## Resume

`out/run.json` is `ree.pipeline.run.v1`. Starting again in that directory without `--resume` is an error. `--resume` keeps `run_id`, skips a stage whose checkpoint is `passed` and whose output files still exist, and retries the first stage that is not reusable. A passed stage with a missing output is run again. Changing `--approve-*` flags makes the guard and handoff stages run again. Changing `--improvements` or `--no-improve` makes improve and the stages after it run again. Earlier checkpoints stay as they were.

## Approval flags

`--approve-launch`, `--approve-guard`, `--approve-blast`, `--approve-scale`, and `--approve-vault` record that a person asked. They do not perform the sell action.

- `dry_run` stays true.
- `notified_blast` stays false.
- `notified_scale` stays false.
- Guard `sign_off` stays `not-submitted`. The note says Guard was not called.
- `approved_for_vault_copy` stays false. `approval_requested` may be true.
- `launch_approved` is true only when `--approve-launch` was passed. That is a record, not a launch.
- If `/home/box/shared` exists and `--approve-launch` was passed, the handoff directory is copied to `/home/box/shared/ree-to-blast/<build_id>/`. Blast is still not notified. On a machine without that directory, the files stay under `--out`.
- Launch, publish, and payment stay unperformed even when an approval flag is set. `--approve-launch` sets `launch_approved`. `--approve-vault` records payment intent. No publish flag exists, and nothing is published. No payment is taken.

## Shared board from package

The package stage writes into a shared directory only when that directory already exists. `REE_SHARED_BOARD` is used when it is set and the directory exists. A set value that does not exist is not created, and the stage does not fall through to the box path. When the variable is unset, `/home/box/shared/ree-board` is used only if that directory exists.

- `findings/<id>.md` is one file per spec feature or endpoint. `<id>` is `fnd_` plus 16 hex characters, the same id the handoff stage later writes as `ree.board.finding.v1`. The markdown records kind, name or route, match, and redacted citation URLs. It does not copy spec quotes.
- `board.json` gains a `runs` entry (`ree.shared.run.v1`) for this `run_id`. An existing `items` array and note are left in place. A second package write for the same run replaces that run entry.
- `requests/guard.json`, `requests/blast.json`, and `requests/scale.json` are `ree.handoff.request.v1`. `called` is false and `dry_run` is true.
- The Guard verdict request is the same JSON as `requests/guard.json`. It is written to `/home/box/shared/guard/verdicts/<build_id>.json` only when `/home/box/shared` exists. Otherwise it is written to `guard/verdicts/<build_id>.json` under the run directory. `<build_id>` must be `bld_` plus 16 hex characters. The verdict is not written beside an arbitrary `REE_SHARED_BOARD`.
- `shared-board.json` in the run directory records whether a shared directory was used. `run.json` `shared_board` is that directory or null.

`board export --to` still writes `ree.shared.board.v1` and `findings/<opp_id>/`. It keeps an existing `runs` array and does not delete `findings/*.md`. `board picks --from` is unchanged. The studio still shows those agent verdicts.

## Schemas

Checkpoint `ree.pipeline.checkpoint.v1`: `run_id`, `stage`, `status` (`passed` or `failed`), `started_at`, `finished_at`, `message`, `outputs` (paths relative to the run directory), `provenance`.

Run `ree.pipeline.run.v1`: `run_id` (`run_` plus 16 hex characters), `target`, `product_name`, `dry_run`, `approvals`, `stages`, `stopped_at`, `finished`, `code`, `message`, `shared_board` (the shared directory used by package, or null). After improve, `improvements` is `ree.improve.v1`. After handoff, `gaps` is the same `ree.gaps.v1` list.

Findings `ree.pipeline.findings.v1`.

Accuracy `ree.pipeline.accuracy.v1`. `not_the_corpus_bench` is true. Precision and recall use the rebuild plan: a feature is expected when it was given a data model, rules, and CRUD routes. Empty expected and empty observed are null; empty observed and a non-empty expected set are precision 1 and recall 0. A pass that was not expected, or an expected route that did not pass, fails the verify stage. Feature coverage on `experiments/ree-bench/desk` must stay at or above 0.8. `FEATURE_REPORT.md` lists implemented features and each feature left out, with the reason.

Handoff files, under `handoff/<build_id>/`:

- `ree.blast.handoff.v1` in `handoff.json`. `gaps` is `ree.gaps.v1`, the same list as the README section What we can't read or build yet. A line that would repeat the spec target name is omitted. The list is not a percentage of the original product. `improvements` is the same list as the README section What we do better. Each item is marked improvement. A quote that would repeat the spec target name is omitted.
- `ree.guard.submission.v1` in `guard/submission.json` (also copied to `out/guard/submission.json`)
- `ree.scale.handoff.v1` in `scale/manifest.json`
- `ree.vault.manifest.v1` in `vault/manifest.json`
- `ree.handoff.request.v1` in `requests/guard.json`, `requests/blast.json`, and `requests/scale.json`. `called` stays false.

Board files, under `board/`:

- `board.json` is the opportunity list.
- `findings/<id>.json` is `ree.board.finding.v1`, one file per spec feature or endpoint.
- `picks/<id>.json` is `ree.board.pick.v1`. A pick is a feature whose route test passed. A feature left out is a finding and is not a pick. The finding records the reason.

`node ree.mjs board picks --data DIR` lists the pick files. `node ree.mjs board export --data DIR --out DIR` copies findings, picks, and the request files. Export does not call Guard, Blast, or Scale. The studio Board screen lists the picks from pipeline runs in its data directory.

`node ree.mjs board export --to DIR` writes that Opportunity Board for other agents. `DIR` defaults to `REE_SHARED_BOARD`. `DIR/board.json` is `ree.shared.board.v1`. Each item has `id`, `title`, `what_it_does`, `findings_summary`, `bench_accuracy_confidence`, `buildability_score`, `scout_market_notes`, `status`, and `kind`. `bench_accuracy_confidence` stays null unless a bench record is stored. A Scout buildability score is `scores.build_ease` and is not rescored. A spec has no buildability score. `DIR/findings/<id>/report.md` and `spec-draft.json` are drafted from stored facts. Quotes are not copied. URL usernames, passwords, and credential query parameters are removed. This export does not call Guard, Blast, or Scale.

`node ree.mjs board picks --from DIR` reads `DIR/picks/*.json`. Each file has `agent`, `id`, `verdict` (`build`, `skip`, or `maybe`), `reason`, `angle`, and `date`. The studio Board shows those verdicts beside the matching entry. A file with another verdict is reported and is not shown as a pick. `--data` still lists pipeline pick files.

Scale's `approved` field mirrors `--approve-scale`. `notified_scale` stays false. `package` is `product.tgz`.
